# Human Decision Gates

Use this reference for every real website project. The workflow is collaborative by default.

## Participation Modes

- **Collaborative Mode — default:** pause at every mandatory gate and ask for a user decision.
- **Delegated Mode:** the user delegates one named decision; record the assumption and continue only through that gate.
- **Autonomous Mode:** use only when the user explicitly requests a one-pass result, dry run, or full delegation. Preserve the gate outputs in the final decision record.

Do not infer Autonomous Mode from urgency, a detailed brief, or permission to “continue.”

## Response Pattern At A Gate

Provide:

1. `What we learned`
2. `Options you can inspect`
3. `My recommendation and why`
4. `Decision needed from you`

Ask no more than three questions in one round. Questions should request choices or corrections that materially change the next stage.

## Gate 1 — Brief Calibration

Show the concise brief, facts, assumptions, unknowns, and the most consequential tension.

Ask the user to:

- correct the audience, page job, or core offer;
- choose between competing priorities;
- confirm what success action matters most.

Do not begin competitor research until the minimum intake gate is met.

## Gate 2 — Competitor Preference

Research broadly, then curate three to five references the user can realistically compare. For each reference provide:

- company and direct official website link;
- screenshot or visible-page capture when available;
- positioning/content pattern;
- visual grammar;
- what is reusable;
- what should not be copied;
- fit and risk for the current project.

Do not return only a link dump or a finished conclusion. End with these decision prompts:

1. Which one or two references feel closest to the desired direction, and why?
2. Which reference should become an anti-reference?
3. Should the direction borrow mainly from content structure, visual language, or interaction?

The user may answer with a company name, ranking, partial preference, or “none.” Treat “none” as useful evidence and generate a new reference set.

Do not finalize the design thesis before this gate is resolved.

## Gate 3 — Visual Direction

Create three to five meaningfully different routes. Show comparable artifacts rather than describing them only:

- image samples, page captures, moodboards, or lightweight prototypes;
- the same core content across routes where possible;
- fit, differentiation, extensibility, implementation cost, and risk.

Ask the user to choose:

- one primary route;
- one optional route to borrow from;
- elements to reject.

Do not fuse routes or declare a winner without user approval.

## Gate 4 — Architecture And Public Content

Show:

- proposed page sequence;
- hero message and CTA;
- proof/case strategy;
- content still awaiting evidence.

Ask the user to approve or reorder the page narrative and correct product claims. Do not hide unresolved claims inside polished copy.

## Gate 5 — Implementation Path

Show the feasible paths with evidence: Figma-first, HTML-first, no-code/Framer, prompt-to-image exploration, or another relevant route.

Ask the user to confirm:

- target deliverable;
- chosen path;
- fidelity, speed, and editability priority.

Do not commit to a production path based only on the agent's score.

## Gate 6 — Final Handoff

Before final delivery, show unresolved decisions, assumptions, omitted evidence, and what remains editable. Ask for a final correction pass when the user is still actively collaborating.

## Waiting Behavior

While awaiting a decision, the agent may:

- organize sources;
- prepare neutral comparison tables;
- verify facts;
- label pending content.

It must not:

- make the blocked choice;
- generate a final direction that makes alternatives costly to revisit;
- present an assumption as user approval.
