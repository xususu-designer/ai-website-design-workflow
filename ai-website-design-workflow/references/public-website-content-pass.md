Use this before finalizing website copy, HTML content, Framer prompts, Figma page text, or no-code page content.

## Public Narrative

Write the page as an external offer:

> [Company/product] helps [audience] achieve [business outcome] through [core platform/product], covering [solutions/scenarios] with [service or proof model].

## Section Copy Matrix

| Section | Public User Question | Website Copy Must Explain | Avoid |
| --- | --- | --- | --- |
| Hero | What is this and why should I care? | Positioning, core offer, primary outcome, CTA | Style names, process labels, validation wording |
| Platform / Product | What is the product? | Capabilities, architecture in business terms, integration value | "This direction", "this version", "prototype" |
| Solutions | Where is it used? | Industry scenarios, user jobs, business outcomes | Generic feature lists without domain meaning |
| Services | How does it land? | Consulting, implementation, operations, support | Internal workflow stage names unless customer-facing |
| Trust | Why believe it? | Proof, certifications, case types, governance | Unsupported metrics or fake customer claims |
| CTA | What should I do next? | Consultation, demo, trial, assessment, contact | "Download placeholder", "next validation" |

## Internal Language Blacklist

Remove these from public pages unless the user explicitly wants a design case study:

- style direction labels: Basic, Perspective, dramatic, refined, etc.
- brand-reference labels: Tesla-like, IBM-like, Linear style, NVIDIA calibrated
- process labels: validation path, output sampling, design thesis, prototype QA
- design rationale: "this version uses...", "the risk of this direction is..."
- artifact labels: placeholder, evidence slot, sample, prototype, direction
- unsupported caveats: "do not fake metrics", "waiting for real content"

## Claim Integrity

Classify each claim before publishing.

| Claim | Source | Status | Public Handling |
| --- | --- | --- | --- |
|  |  | Fact / Source-provided / Assumption / Unsupported | Use / Qualify / Remove |

Use source-provided metrics only if the user supplied them as approved content. If metrics look like placeholders, either remove them or mark them as needing confirmation outside the public page.

## Final Content QA

- The page can be read by a customer without seeing the design process.
- The first viewport states the company/product, audience, core offer, outcome, and CTA.
- Product sections explain capabilities, not just visual metaphors.
- Solution sections map to concrete industry scenarios.
- Service sections explain how adoption happens.
- Names are consistent in visible text, metadata, alt text, SVG text, and accessibility labels.
- Visual references influence styling only; they do not appear as website copy.
